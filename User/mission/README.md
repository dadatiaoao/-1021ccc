# 比赛纯调度框架（未接入执行器）

2026-10-27 根据用户选择合入框架，不合入 K230 通信。

保留 mission.c/h 的两批搬运步骤、三槽逻辑状态、三件全部粗加工放完再取回的屏障、同色码垛映射、一次启动、停止与失败处理。mission_config 提供空路线配置及验证，未填写猜测路线。框架仍使用固定启停区2约定，正式部署前需要确认起点。

正常应用以全零 MissionPort 初始化。没有 blocked/begin/poll/stop 执行接口，因此 START 拒绝，既不会移动底盘，也不会抓放。比赛页仅用于展示未完成状态。未合入 mission_runtime、视觉协议、USART1 DMA或K230心跳；原USART1调试行为保持不变。

后续接入：通过 MissionPort 提供就绪检查、动作提交、按 request_id 查询完成及停止回调；真实扫码结果也由执行器交回。只有完整动作结束才返回 SUCCEEDED，不把入队或ACK当作到位。连接之前还须完成应用层独占控制仲裁、实际路线与抓放姿态、K230按钮READY/START握手，以及舵机动作时间验证。

统计口径：SOURCE_TO_SLOT和ROUGH_TO_SLOT各累计外部抓取；SLOT_TO_ROUGH和SLOT_TO_STORAGE各累计对外放置。两批各12次，车载槽内部抓放不重复计数。均为动作完成推定，不是物料反馈。

验证：Scripts/test_mission.ps1 穷举25920组两批任务，检查34步顺序、同色映射、三件放完屏障、12/12计数、重复启动、失败与STOP。执行结果为替身，不证明实车搬运成功。
