# 启停区 2 比赛主程序

2026-10-24 用户决定首版固定启停区 2 发车、返回启停区 2。取消本版起点自动识别和 1/2 选择；不再等待起点编号配置。

## 已接入的程序

- `mission.c/h`：非阻塞比赛调度，真实主循环每轮推进。启动一次，完成/中止后不得再次发车；未就绪的启动直接拒绝，恢复就绪后仍需重新按启动。
- `mission_runtime.c/h`：连接现有 Chassis、MotorBus 和 K230 VisionService。路线按绝对目标点逐段平移、停车确认、旋转；扫码使用 K230 的既有模式 0，获得合法任务并确认视觉 STOP 后才进入下一阶段。
- `mission_config.c/h`：六条路线的配置入口；坐标、出发姿态和现场通行情况必须经过确认。默认没有填入猜测的路线。
- `mission_ui.c/h`：显示固定起点、阶段、任务码、槽位、粗加工/暂存状态、未就绪原因和按完整动作推定的计数。
- `QrApp`：持有并推进 Mission。任务执行期间禁止手动动作、底盘验收、重新扫码、视觉联调和传感器清零等操作抢占任务；STOP 先中止整场任务，再保留原有停车处理。

## 操作入口

保留上电 QR 页。点击第二行会话状态（y=32～51）进入 `RACE ZONE 2`，底部 START 请求启动，STOP 全局停止，BACK 或标题返回。换页不暂停后台任务。

本页 START 是联调入口。此前约定的 **K230 板上实体按钮 → READY/START 串口握手** 本次仍未实现；没有猜测实体按钮 GPIO。后续接入时必须调用统一的 `QrApp_StartMission()`，不得绕过就绪检查。正式比赛的一键入口还需完成这部分。

## 已编排的完整顺序

启停区2 → 二维码观察位 → K230扫码 → 原料观察位 → 按顺序取3件并分别放入车上槽1/2/3 → 粗加工观察位 → 三件全部放完 → 按任务顺序取回车上 → 暂存观察位 → 第一批平放 → 返回原料区 → 第二批按同样流程完成粗加工 → 暂存同色码垛 → 空爪/机构收拢 → 返回启停区2。

任务码仍是 `C1+P1+C2+P2`。P2 只控制第二批粗加工位置；第二批暂存位置用颜色查找第一批 P1，层号=2。程序记录三个车上槽、三个粗加工工位及三个第一层暂存颜色，动作完整成功后才更新。第二批同色顺序变化不会改变码垛位置。

一次正常流程有34个调度动作，其中24次完整转运。一次转运是“抓取→车载槽/工位释放→收回”，正常完成后各增加一次抓取/放置计数，包含车载槽的抓放。这些是动作推定值，不是传感器确认物料成功的统计；若采用其他评分统计口径，需要另行区分。

## 为什么默认显示 NOT READY

现有资料未提供本车机构限位/零点、舵机职责/PWM、三槽坐标和实测路线；不能用 ACK、等待几秒或 YOLO 框假装这些动作完成。因此本次交付的是**可执行的任务调度及底盘/扫码适配层，尚不是能直接完成整场比赛的实机程序**。

| 页面缺项 | 需要接入或标定的内容 |
|---|---|
| BASE | `User/chassis/chassis_config.h` 的轮径、轴距/轮距、减速比、四轮方向、光流比例/安装及确认标志 |
| ROUTE | 六条路线、初始摆放朝向、整车通行包络、随机障碍检查接口 |
| ARM | 真实回零、命名姿态、两个舵机、三槽取放和转运执行器；未注册硬件接口或回零未完成时拒绝启动 |
| VIS | K230串口可用、心跳新鲜，视觉处于IDLE/STOPPED；联调扫描需先停止 |
| SENSOR | 光流/陀螺可用且连续、四轮反馈新鲜健康、零速和停车确认 |
| BUSY | 手动模式、其他底盘任务或底盘故障尚未解除 |

不要把确认标志直接改成1来消除缺项；它们需要对应真实数据和执行器。

## 路线怎么填写

`Mission_DefaultConfig()` 是唯一默认路线入口。坐标系原点是按 START 时底盘参考点的位置；X 正方向为当时车头，Y 正方向为车身左侧，角度逆时针为正。地图方向需要在赛前以摆放朝向映射到此坐标系。相机的朝向/观察姿态也必须与路线终点匹配。

所有目标点都相对同一个出发原点；不是“相对上一点走多远”。运行时使用光流累计位置和陀螺角度转换到当前车身位移。途中视觉对准改变底盘位置后，下一条路线仍使用实际里程计位置计算剩余距离。

六条路线依次是：

1. HOME_QR：启停区2→二维码观察位。
2. QR_SOURCE：二维码观察位→原料观察位。
3. SOURCE_ROUGH：原料观察位→粗加工观察位。
4. ROUGH_STORAGE：粗加工观察位→暂存观察位。
5. STORAGE_SOURCE：暂存观察位→原料观察位。
6. STORAGE_HOME：暂存观察位→启停区2；最后一点必须是 `(0,0,0)`。

每条最多8个目标点，设置 count 和 confirmed；初始摆放确认后设置 initial_pose_confirmed。轨迹按“先平移、停车，再在该点旋转”执行；需要绕开边界或障碍时必须增加经验证的中间点，不会自动规划绕障。返回原点只是里程计闭环；尚无蓝色启停区边界识别及整车入区视觉验收，需预留停车误差并实测。

`MissionHardware.path_clear()` 在每段及运动过程中检查是否可通行；目前没有自动绕障实现。禁止用恒定返回1代替现场障碍/边界验证。检测到阻碍走任务停止流程。

## 机械臂接口在哪里接

在应用初始化后、允许启动前，使用 `MissionRuntime_SetHardware(&app.mission_runtime, hardware)` 注册接口；不得在比赛运行中替换。

- ready：机构确实完成回零、收拢，能够执行比赛动作。
- begin：只提交该 request_id 的完整动作；返回1仅表示接收，不能算完成。
- poll：分步执行，WAIT表示继续；只有相关电机执行完成、舵机标定时间结束、机构撤回且底盘停稳，才能返回 SUCCEEDED。动作可调用同一 Chassis 作空载对准，但取料/垂直放置阶段必须冻结底盘。
- stop：取消机构后续动作，不自动失能承重升降轴；底层仍由同一 MotorBus 负责停止确认。
- path_clear：当前路径/转弯包络及障碍检查。

四类转运动作分别是原料→车载槽、车载槽→粗加工、粗加工→车载槽、车载槽→暂存；颜色/槽号/工位均在 `MissionAction` 中。STOW 需要独立完成空爪和收拢。本次没有实现这些硬件动作，也没有把它们默认返回成功。

随臂相机的观察姿态、空爪对准后保存目标姿态、取车载物料后返回保存姿态并垂直放置，由机械臂执行器完成。大圆环YOLO框不能直接当最中心小环的精确定位；执行器仍需使用标定的精定位结果。视觉串口的 zone=1/2 继续表示粗加工/暂存，与固定启停区2无关。
