# 板上检查、采样与标定

## 1. 安装与模型

在 CanMV 中运行 `/sdcard/tools/check_install.py`。它只读取文件并检查配置、两个模型的哈希及标签对应，不初始化 UART、摄像头或舵机。出现 MODEL_OK 和 INSTALL_OK 后，再运行预览。模型 manifest 记录原有模型，不代表验证了识别精度。

## 2. 编号大圆环与真实中心

先运行 `tools/preview_models.py` 验证 R1/R2/R3 对应真实位置数字，不随左右顺序变化。再运行 `tools/preview_rings.py`，默认观察位置1；要看其他位置可在该工具中修改测试位置或通过正常入口发送 SET_TARGET。

黄色框和黄色十字为圆环 YOLO 框及框中心；额外紫色十字是当前帧几何圆族中心候选。没有紫色十字时，查看底部原因：NO_FAMILY、AMBIGUOUS_FAMILIES、OBLIQUE_VIEW、ROI_TOO_SMALL 或 REFINE_API_ERROR。不要把框十字当作几何拟合成功。

该模块引用同一 YOLO RGBP888 帧的 G 通道作为灰度数据，仅对目标框做原生 find_circles；不另拍一个可能错时的 RGB565 通道。黑白圆线适合这种灰度近似，实际对比度和 CPU 耗时须检查。API 依据 [CanMV 图像 API](https://www.kendryte.com/k230_canmv/en/main/api/openmv/image.html)及[官方圆检测示例](https://github.com/kendryte/canmv_k230/blob/canmv_k230/resources/examples/25-Compare/openmv_find_circles.py)；固件不支持时不伪造精定位结果。

至少需检测到3个相隔足够半径的同心圆候选，并通过中心一致性、ROI边界及近正视筛选。一条圆线的相近内外边缘不能当成3条独立评分环。检测到的最小圆不自动命名为“最内侧评分1环”，输出只表示圆族中心候选。多个圆心的平均数可能带小数，不代表算法已达到亚像素物理精度。

用 `tools/capture_ring_sample.py` 在固定姿态保存一张无叠加的 BMP；它独立占用相机，先停止其他视觉脚本。记录：目标编号、相机姿态、相机/目标平面高度、前视或斜视、距离、遮挡、光照、外部人工标注中心。重复覆盖三个编号和实际观察距离。

如果画面明显呈椭圆，不应通过放宽 RING_MIN_ASPECT 和中心误差阈值来假装圆形模型有效。需要带实际标定数据的平面矫正或椭圆拟合；本轮尚未实现该部分，不能宣称已精确得到最内环。

## 3. 转盘抓前候选

`tools/preview_pick.py` 默认测试红色。PICK_ROI、MATERIAL_ROI 和 RING_ROIS 都用 640×360 AI 像素，格式 x,y,w,h；不使用缩放后的协议像素。多个同色框出现时，通过实际抓取窗口限制 ROI，而不是提高置信度后任取一个。

默认至少4个新帧、跨度300ms、500ms窗口、相邻间隔不超过250ms，中心漂移不超过4像素，框尺寸变化不超过8%。这些是联调起点，不是已标定的赛题阈值。处理过慢、重复帧、目标丢失、跳变和任务切换都会阻止稳定累计。

静止图像可能来自相机跟着目标走，也可能来自慢运动、采样混叠；因此 STABLE 不是转盘物理停稳证明。只有验证了抓取 ROI、相机姿态、转盘双向运动、实际停留窗口及机械执行延迟，才设置 PICK_CALIBRATED=True。该标志仅启用抓前候选，不检测抓住/入槽/释放后的物料状态。

## 4. 标定与放置验收记录

复制 calibration/measurement_template.json 后填写真实数据。模板不会自动进入运行配置，默认所有用途标定标志为 False。

- 比较框中心、几何中心与人工标注中心的像素误差，保存失败样本。
- 分别记录平放层和第二层物料顶面的姿态/高度；不能把地面环中心直接代替上层支撑面中心。
- 验证底盘冻结、回车取料、机械臂返回后的真实落点及释放偏移；不要只看图像误差归零。
- 记录 640×360 的细圆线可分辨程度；最内环不足数个像素时，当前分辨率可能不够，不能仅把输出坐标乘2提升精度。
- 记录双模型和局部拟合后的处理时延、有效结果频率；默认超过300ms的观察作废，不能为了隐藏慢帧随意放宽。

完成证据后再考虑启用 RING_REFINEMENT_CALIBRATED 和 PLACE_CHECK_CALIBRATED。它们不自动证明裁判评分、成功释放、有效底层或稳定码垛。所有毫米误差以外部实际测量为准。
