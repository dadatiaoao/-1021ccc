# UART 协议与新增质量观察

链路：K230 UART2 IO11/TX → F429 PA10/RX；IO12/RX ← PA9/TX；GND 共地。115200/8N1，3.3V TTL。配套 STM32 工程已关闭 USART1 的 printf 文本并接入协议收发、上下文过滤和视觉联调页。接线与使用见 [STM32 联调说明](../../主控板程序/Doc/K230_串口协议与联调.md)。

## 基础包

`AA LEN CMD PARAMS SUM`。LEN=CMD 与参数总字节数，1～13；整帧 LEN+3，最多 16 字节。SUM 为 CMD 与参数相加取低 8 位。u16 高字节在前，偏移角为 int16 补码，单位 0.1°。无 CRC、无自动重传；ACK 不是动作完成信号。

| CMD | 方向 | 参数 |
|---|---|---|
| 10 | K230→主控 | 12 个数值字节任务码，非 ASCII，已去除 + |
| 11 | K230→主控 | color:u8,cx:u16,cy:u16,offset:i16,distance:u16 |
| 12 | K230→主控 | NOTFOUND，无参数，主控应撤销旧目标 |
| 13 | K230→主控 | zone:u8,pos:u8,ok:u8 |
| 15 | K230→主控 | HEARTBEAT，无参数，约每秒一次 |
| 16 | K230→主控 | pos:u8,cx:u16,cy:u16 |
| 21 | 主控→K230 | SCAN，mode:u8，见下表 |
| 22 | 主控→K230 | STOP，无参数 |
| 23 | 主控→K230 | color:u8，1～6 |
| 24 | 主控→K230 | RESCAN，无参数，保留模式；STOP 后不自动复扫 |
| 25 | 主控→K230 | zone:u8(1粗加工/2暂存),pos:u8(1～3) |
| 26 | 主控→K230 | 可选 SET_CONTEXT，request_id:u16,camera_pose_id:u16 |
| 81 | K230→主控 | 原命令:u8,status:u8，0接受/1参数错误 |

表内 CMD 均为十六进制。任何合法控制会清理旧观察、稳定窗及扫码一致性状态。无效命令不会重置二维码超时。相机移动或进入新阶段，应更新 camera_pose_id/request_id，再派发模式及目标；推理期间发生更新会丢弃旧帧结果。

| SCAN mode | 行为 | 结果含义 |
|---:|---|---|
| 0 | 连续三次一致的合法二维码 | TASKCODE 一次性锁定，超时 NOTFOUND 一次 |
| 1 | 物料粗定位 | FOUND 颜色及检测框中心 |
| 2 | 编号大环粗定位＋原放置检查接口 | RING 仍发框中心；默认 PLACE_CHECK=0 |
| 3 | 转盘抓前目标观察 | FOUND 粗坐标；是否稳定/可抓见扩展标志 |
| 4 | YOLO ROI 内几何圆族中心候选 | 拟合有效才发 RING，失败发 NOTFOUND，绝不回退到框中心 |

模式 2 的 PLACE_CHECK=1 必须同时具备人工实测标定开关、几何候选及连续稳定条件。即使它为 1，也仅表示配置的图像候选判据成立，不能用于自动推导裁判环数、实际释放成功或码垛成功。

## 可选扩展观察 0x17

只有主控发送过合法 SET_CONTEXT(0x26) 后才启用；没有 SET_CONTEXT 时不发送新包，基础格式保持不变。启用后模式 1～4 每次基础结果后附加观察包。配套 STM32 的 vision_service 已实现该扩展解析与请求/姿态/帧过滤；其它旧解析器仍需增加相应支持。

12 字节参数：

```text
request_id:u16 | camera_pose_id:u16 | frame_id:u16 |
flags:u8 | target_id:u8 | cx:u16 | cy:u16
```

frame_id 是本次运行的采集调用序号（16位回绕），不是传感器硬件帧号或两板共享时间戳。目标为当前颜色或位置号。cx/cy 均为 1280×720 协议像素；它们由 640×360 缩放而来，不提高实际图像分辨率，也不是毫米。

| flags 位 | 意义 |
|---:|---|
| 0x01 FOUND | 本次有唯一有效目标 |
| 0x02 STABLE | 新帧在位置、尺寸和时间窗内稳定 |
| 0x04 PICK_READY | 模式3且抓取 ROI/标定已配置并稳定，仅是抓前候选 |
| 0x08 FULL_BOX | 检测框未被图像边界截断 |
| 0x10 AMBIGUOUS | 当前 ROI 内有多个相同目标，不返回任选坐标 |
| 0x20 CALIBRATED | 对应用途的本机人工标定标志已设置 |
| 0x40 REFINED | 来自局部多半径圆族中心候选，不是框中心 |
| 0x80 STALE | 本次处理时延超过配置上限，观察无效 |

没有 FOUND 时 cx/cy=0；主控必须先看有效标志，不能把零坐标当真实目标。模式 2 基础 RING 是粗中心，扩展包若有 REFINED 则是几何中心，主控必须明确选择用途，不混合两者。需要精定位的主控应使用模式4及质量标志，并核对请求、姿态和本地接收时效。

例：设置请求号1、相机姿态号2：`AA 05 26 00 01 00 02 29`。环位2仍须先 SET_TARGET；开始几何模式：`AA 02 21 04 25`。每个控制先等 ACK，再派发下一项；目标丢失、换姿态或超时立即作废上一结果。

接入顺序：收 HEARTBEAT → 发控制并收 ACK → 显示基础结果 → 加入扩展解析并验证请求/姿态切换 → 连接已标定的动作层。不要在 UART 中断里运行视觉业务或直接驱动电机。
