# 陀螺仪 WHO_AM_I / 单次软复位对照测试

目的：判断不执行正常初始化时，身份读取是否已经失败；若稳定，观察加入一次软复位后通信是否变化。本测试不判断模块损坏，也不提供角速度、角度或校准结果。

## 编译开关

`User/gyro/gyro_config.h` 中 `GYRO_COMM_TEST` 当前默认 **3**，重新编译并烧录 STM32 固件生效：

| 值 | 行为 |
| --- | --- |
| 0 | 恢复正常陀螺仪初始化、配置与采样 |
| 1 | 持续只读 WHO_AM_I，不发送任何配置/复位写入 |
| 2 | 前 1000 次身份读取全部正确后，检查 Bank 0，再尝试一次软复位，继续只读身份 |
| 3 | 只读身份，第一次总线错误后停止通信、释放 STM32 引脚并持续观察电平（当前默认） |

测试开始只初始化一次 STM32 I2C1；约 3 ms 后开始读取 `0x75`，每次事务结束至少间隔 10 ms，不追赶漏掉的轮询。成功定义为 I2C 返回 OK **且**读值为 `0x47`。正常初始化、配置表、自动重新初始化、退避恢复、采样、积分和固定偏置均被绕过。普通寄存器读取仍会在 I2C 上发送寄存器地址，这不属于配置寄存器写入。

模式 2 的流程：

1. 前 1000 次全部正确（至少约 10 秒），进入 BANK 阶段。只读 `0x76`，必须成功且值为 `0x00`；不主动切换 bank，避免引入额外写入。
2. 下一次处理仅写一次 `0x11=0x01`，进入 POST。沿用现有初始化的 2 ms 等待后开始读取身份。
3. 复位写入即使 NACK/TIMEOUT 也不重发，不重新初始化 I2C。POST 表示“复位尝试之后”，不代表已证实复位成功。
4. 前 1000 次中有任何失败或错误 ID，或 BANK 检查失败，则保持 HOLD，继续只读身份；后续恢复也不再自动发复位。重新复位 STM32 才开始新一轮。

若仅复位 STM32，模块可能保留上一固件留下的 bank/配置状态。本测试不会先切 Bank 0，因此这一条件下的错误 ID 也可能与残留 bank 有关，不能单独证明电气故障。BANK 非零会阻止测试向未知 bank 写入软复位。

## 屏幕读法

打开陀螺仪页面；点击 **MORE** 可看到全部八行。测试中校准/角度清零按钮隐藏，相关服务调用也不会改变统计。

| 显示 | 意义 |
| --- | --- |
| TEST2 PRE / BANK / RESET / POST / HOLD | 测试模式与阶段；HOLD 表示取消本轮软复位尝试，继续只读 |
| ID:47、OK/NACK/TIMEOUT/... | 最近一次事务的身份读值及总线结果；读取失败时 ID 显示 00，不能视为真实芯片身份 |
| PRE:1000/1000 100.00% | 复位尝试前：正确身份次数 / 读取总次数；模式 1 和 HOLD 会持续累计 |
| POST:997/1000 99.70% | 复位尝试后：正确身份次数 / 读取总次数；0/0 -- 表示尚未开始 |
| RST:-- / OK / NACK / ... | 未尝试复位 / 复位写事务结果；OK 不等于已验证复位完成 |
| INIT:OK / IO | STM32 I2C1 初始化结果；初始化失败不会继续访问或自动恢复 |
| BANK:-- / 00 / 01 / NACK / ... | 未取得 bank / 检查读值 / bank 读取失败原因 |
| PRE、POST N / T / B | 各阶段 NACK / TIMEOUT / BUSY 类次数；B 合计普通 BUSY、线低和 HW_BUSY，首行显示当前具体错误 |
| PRE、POST BADID / OTHER | I2C 读取成功但值非 47 / 其余总线错误次数 |

PRE、POST 不包含 BANK 检查及复位写事务，这两项单独显示。成功率按累计计数计算，截断到小数点后两位。统计只保存在 RAM，STM32 复位或断电就清零；离开页面不清零。请在下一轮前拍照记录。

## 三种上电条件的对照

保持接线、电源、固件和测试时长一致。上电方式由人操作并记录，程序不能自动识别。建议每种先做 5 轮，每轮启动约 30 秒后拍 MORE 页面，记下实际读取总数。模式 2 下 PRE 通过后会自动进行 POST，不需要点击按钮。

1. **同时上电**：整机断电后，同时给模块和 STM32 上电。
2. **陀螺仪先上电**：整机断电后，模块先上电，固定等待例如 1 秒，再启动 STM32；记录实际间隔。
3. **仅复位 STM32**：模块保持供电，仅复位 STM32；记录复位前是成功运行、POST、HOLD 还是故障，以免把不同残留状态混在一起。

使用现有可控供电方式，避免带电反复插拔 SDA/SCL。若只能整体供电，应如实记录无法单独比较的条件。

| 条件 | 轮次 | 复位前状态 / 上电间隔 | PRE 正确/总数 | POST 正确/总数 | 阶段 | RST / INIT / BANK | N/T/B、BADID/OTHER | 照片 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 同时上电 | 1–5 | | | | | | | |
| 陀螺先上电 | 1–5 | | | | | | | |
| 仅复位 STM32 | 1–5 | | | | | | | |

判断方向：PRE 已失败时，故障不依赖本轮软复位或配置表；PRE 稳定而 POST 失败时，应进一步核对复位时序和总线事务；两段稳定但正常模式失败时，再逐项恢复配置测试。复位后最初几次失败与持续失联要分开观察，累计成功率不能替代波形定位。

## 2026-11-05：释放 STM32 引脚的诊断（TEST3）

前次 TEST2 实物结果：同时上电两次分别为 3/3541、13/9381；陀螺先上电为 16/5808；仅复位 STM32 为 9/6433。四次均 HOLD、RST:--、POST:0/0，截图时均 BOTH_LOW。这表明本轮未发软复位或配置表也能失败，尚不能判定哪一侧拉低。BUSY 类计数包括总线预检查拦截，不等于已完成的 I2C 事务数量。

新默认模式 3 保留原模式 0/1/2。启动后只读 WHO_AM_I，第一次总线错误（NACK、TIMEOUT、BUSY、线低或 IO）发生后：

1. 锁存错误和读取计数，采样 PB6/PB7 及 I2C1 BUSY 位。这是**错误返回后、释放前**的状态，不是事务中发生错误瞬间的波形。
2. 禁用 I2C1（清 PE），把 PB6/PB7 从复用开漏改为 GPIO 输入、无上拉/下拉。即使外设未因清 PE 释放传输，也通过断开引脚复用解除控制。不会主动发送恢复时钟或新的寄存器事务。
3. 非阻塞等待至少 10 ms（实际还受主循环调度影响）后采样并锁存 AFTER10。其后约每 100 ms 更新 NOW，主控引脚始终保持输入。
4. 本轮不再读写陀螺仪、不重新初始化总线、不发软复位。READ 计数停止增长是预期行为。复位 STM32 才开始新一轮。仅错误 ID、但总线返回 OK 时，继续读取并累计 BADID，不触发引脚释放。

打开陀螺仪 MORE 页面：

| 行 | 含义 |
| --- | --- |
| TEST3 READ ONLY / RELEASE WAIT / PINS RELEASED | 正在读取 / 已释放等待采样 / 已取得释放后电平 |
| READ | 触发释放前的正确身份次数 / 总尝试数 |
| FAULT / INIT | 触发释放的总线错误 / STM32 I2C 初始化结果 |
| BEFORE SCL / SDA / BUSY | 释放前电平及外设忙标志；0=低，1=高或忙 |
| AFTER10 SCL / SDA | 释放后首次延时采样的锁存电平 |
| NOW SCL / SDA | 保持输入状态时的最新电平 |
| ID / BADID | 最后身份读值（失败时 00，不代表真实身份）/ 错误身份次数 |
| INPUT / NO PULL / NO RETRY | 已保持输入、无内部上下拉、无通信重试 |

UNSUPPORTED 表示平台没有提供诊断回调，会停止通信；INIT 非 OK 表示初始化失败，不开始读取或释放诊断。

**怎样做实物对照：**同样分别做同时上电、陀螺仪先上电、仅复位 STM32。出现 PINS RELEASED 后拍 MORE 页面，再测模块 VCC、SCL、SDA 对 GND 电压。屏幕只显示数字电平，不能替代电压或波形测量。

- BEFORE 为 0/0、AFTER10 和 NOW 为 1/1：释放主控之后总线升高，支持追查 STM32 外设/引脚/超时退出路径，但不单独证明某个驱动缺陷。
- AFTER10/NOW 仍低：继续检查模块、线路、上拉供电及主控引脚的实际模式；不能仅由此宣判模块损坏。
- AFTER10 与 NOW 不同：存在释放后的状态变化，需记录两者并用波形继续定位。
- 连续读取一直成功：继续等待首次错误；本模式不会因为读够 1000 次就发复位。

分支整理：原 main 上 f75e0ca 之后的 c7baf0b、0010611、765b0bb、843949f 保存在 debug/gyro-i2c-20261105；本地 main 指回 f75e0ca。远端同步时先推送排查分支，再使用明确旧提交的 force-with-lease 将 origin/main 退回 f75e0ca，避免后续 pull 恢复四个排查提交。

## TEST3 首次 HAL 错误与逻辑分析仪（2026-11-05）

详情页底部两行替换为 `FIRST S:n R:75 C1:xxxx` 和
`SR1:xxxx SR2:xxxx E:n`。寄存器值均为十六进制；E=1 表示 AF/NACK，
E=2 表示等待超时。HAL 等待函数在清除 AF、生成错误 STOP 或超时收尾前
调用诊断钩子。仅记录专用陀螺仪句柄的读事务，首次记录冻结至总线重新初始化。
写事务、预检失败、HAL_BUSY 不提供这份内部记录，显示 NO HAL CAPTURE。
这些字段是故障现场快照，不是释放后的寄存器值，也不能代替波形。

阶段 S：1=等待 START；2=等待设备写地址应答；3=发寄存器前等待 TXE；
4=发寄存器后等待 TXE；5=等待重复 START；6=等待设备读地址应答；
7=接收数据。阶段表示软件正在等待的位置，不一定等于线上首次异常字节；
特别是 TXE 并不直接证明寄存器字节已获得 ACK。

诊断仍保持首次通信错误后释放引脚，不重试；未添加释放前的额外延时。
原 ID/BADID 显示让位于错误现场，内部计数仍保留。

### 逻辑分析仪操作

- 使用支持当前信号电压的逻辑分析仪。GND 接公共地，CH0 接 PB6/SCL，
  CH1 接 PB7/SDA；探头线尽量短。只接地和信号，不连接分析仪电源输出。
- 软件添加 I2C 解码，SCL=CH0、SDA=CH1，7 位地址显示，十六进制数据。
  当前总线100kHz，可先用10MHz采样、采集2秒；内存不够可用2MHz。
- 先开始采集，再给板子上电或按 Reset；若不能捕获上电，可触发 SCL 下降沿，
  保留预触发数据。分别保存三种上电条件的原始采集文件和屏幕照片。
- 正常单字节 WHO_AM_I 读：START → 0x68 W → 从机 ACK → 0x75 →
  从机 ACK → repeated START → 0x68 R → 从机 ACK → 0x47 →
  主机 NACK → STOP。8位地址显示模式可能显示0xD0/0xD1。
- 最后读完0x47之后的主机 NACK 是正常结束，不能作为错误触发的唯一条件。
  应重点寻找地址或寄存器字节之后的从机 NACK，并与屏幕阶段对应。
- 放大最后一笔事务，检查 NACK 在哪里、是否生成 STOP、之前是否有错误数据。
  保存正常事务与首次异常事务，截图需包括完整 START 到 STOP，而非仅解码文字。
- 数字逻辑分析仪能判断协议时序，不能可靠判断上升沿形状、振铃或供电波动；
  这些需示波器。不要仅凭解码失败认定模块损坏。
