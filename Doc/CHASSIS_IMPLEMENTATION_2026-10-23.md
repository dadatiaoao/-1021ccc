## 2. 对外调用和结果

公开类型/API 见 [`chassis.h`](../User/chassis/chassis.h)。调用方绑定现有 MotorBus，配置在初始化时复制；准备/运动期间保持配置不变。修改已标定参数后，应在确认停止的情况下重新初始化/重新编译，而非运行中修改正在使用的配置。

```c
/* QrApp 已负责每轮调用 Process，不要额外创建第二套底盘实例抢同一组轮子。 */
Chassis_Prepare(&app.chassis, now_ms);  /* 显式意图；只提交一次 */
/* 持续运行 QrApp_Process，检查快照，等 READY，不在这里忙等。 */

/* 二选一：速度模式周期刷新，或启动一个有限动作。 */
Chassis_SetBodyVelocity(&app.chassis, 100.0f, 0.0f, 0.0f, now_ms);
/* 速度模式：上层建议每 50 ms 用当前目标再次调用。 */

Chassis_MoveRelative(&app.chassis, 300.0f, 0.0f, 100.0f, now_ms);
/* 或 Chassis_RotateRelative(&app.chassis, 90.0f, 30.0f, now_ms); */
/* 有限动作只启动一次，随后查询 Chassis_GetSnapshot。 */
Chassis_Stop(&app.chassis, now_ms);     /* 随时取消；随后仍需 Process 验证停车 */
```

代码片段是独立调用方式说明，不应把速度调用和有限动作连续提交；前一个动作持有四轮时，后一个运动请求返回 BUSY。

- 坐标：前 +x、左 +y、俯视逆时针正角；速度 mm/s、°/s，距离 mm，角度 °。
- 地址 1/2/3/4 = FL/FR/RL/RR。`gear_ratio` 为电机转数/轮子转数；直接驱动也需实物核对后明确填 1。
- `ACCEPTED` 仅表示意图接受。Prepare 等四轮健康静止，异步使能并等待新的状态反馈；总期限 10 s。不请求 5～7 使能、运动或回零。
- 状态与结果分开：DISARMED/PREPARING/READY/VELOCITY/MOVING/ROTATING/STOPPING/FAULT；结果 NONE/RUNNING/SUCCESS/CANCELLED/FAILED。STOPPING 不等于已停止。
- 速度模式合法刷新覆盖目标；300 ms 无新请求则停止并锁定失败。内部 100 ms 重发不能替上层续命；新包租约不超过原始截止时间，剩余不足 100 ms 不再排包。零向量也进入停车确认。
- MoveRelative 的目标在本段起始车体系内，横纵向一起纠偏并保持开始朝向；RotateRelative 只依赖 gyro，保留有符号累计角，+270° 不转成 -90°，首版范围 ±360°。
- 有限动作不可被速度或另一个动作抢占。直接速度不依赖光流/gyro，不承诺地面测速或保向闭环；四轮新鲜健康反馈仍是必要条件。
- 故障或超时不能靠再次发送速度、重复 START 或 STOP 清掉失败。确认停止后须显式 Prepare；屏幕 START 内部重新 Prepare。未确认停车时持续 STOP，不接受新运动。
- `publish_accepted` 为 MotorBus 接受次数，`submitted_frames/last_submit_ms` 来自实际 transport.send 成功提交，均不是机械执行完成；BUS_REJECTED、最大提交间隔及四轮反馈年龄保留诊断。

## 3. 算法和测量边界

`k=(L+W)/2`，omega 从 °/s 换 rad/s，四轮轮缘速度分别为 `vx-vy-k*w`、`vx+vy+k*w`、`vx+vy-k*w`、`vx-vy+k*w`；再乘 `60*gear/(pi*diameter)` 及每轮符号。任一轮超限时四轮同比缩放。整数 RPM 对称四舍五入，不增加最小转速脉冲。

内部最多每 20 ms 计算一次，使用实际 dt，不补跑积压周期；100 ms 发布最新四轮目标。平移比例 Kp=1.5/s、角度 Kp=2.0/s、角速度阻尼 0.2，平移/角向加速度初值 200 mm/s²、60°/s²，限速 100 mm/s、30°/s。接近目标还受 `sqrt(2*a*remaining)` 制动包络限制。驱动加速度字段 100 是协议参数，不能理解成 mm/s²。全部是待实车验证的控制初值。

里程计只维护当前 gyro 连续段内的局部坐标。动作保存最近成功配对的光流位置和当时 gyro 角度作为起点，不清零共享服务；准备时要求电机静止，起点仍受采样时间分辨率/时延限制。新光流必须与最近两个有效 gyro 时间戳配对，插值求姿态，等待未配对样本而不外推。同一连续段可用累计 counts 差值吸收未逐次消费的样本。

光流安装角作用于 FlowSnapshot 已映射的 X/Y，不能重复应用 `FLOW_SWAP_XY/FLOW_*_SIGN`。相邻采样间用中间朝向变换平移，再减去 `(R_new-R_old)*sensor_offset`。无论样本值是否看起来正常，光流 rejected/gaps/segments/clears/overflow 或 gyro ZERO/CAL/重启/断轨变化都使当前相关动作失败。平移需光流≤100 ms、gyro≤30 ms；旋转仅需 gyro，单独光流失效不阻止旋转。序列段间也检查下一段必需的传感器及连续性。

平移≤10 mm 且朝向误差≤2°，旋转误差≤2°，实测角速度≤3°/s，**新测量连续满足 200 ms**才请求停止。必须等 MotorBus 的新鲜零速/状态确认，再取得停车确认之后的测量重新检查，才给 SUCCESS；停稳后越界报告 FINAL ERROR。动作期限为 `5 s + 3*距离/速度` 或 `5 s + 3*角度/角速度`，上限 60 s。停车 3 s 未确认记失败，仍持续重试，不推进下一段。

300 ms 是软件发起停车的期限，依赖 MCU 继续运行与通信可用；不是机械停稳保证，也不是驱动端硬件看门狗。保持现有 UART 故障与 STOP 未确认语义。

## 4. 屏幕操作

上电 QR → 右下 MOTOR → 点击左上 `CHASSIS [tap] / MOTOR` → 底盘视图。

- 左下 START：完整配置、必需测量及四轮准备通过后只执行一轮。长按/重复 START 不重启运行中的动作。
- 左上标题：BODY/WHEELS 切换。BODY 显示段号、目标/当前位姿、速度、测量/停车状态；WHEELS 显示各轮目标/实测 RPM。无效或过期反馈显示 `--`。配置不全时列出确认标志、几何参数缺项、方向和光流缺项。
- 顶部 FLOW/GYRO：继续查看原诊断页；BACK 逐层返回。切页不取消动作，不停止后台采样。闭环/序列及四轮占用期间拒绝 FLOW CLEAR、GYRO ZERO/CAL；四轮手动使能/运行、四轮组/同步、模式切换不能抢占，显示 CHASSIS BUSY。
- 底部 STOP：先取消底盘意图，再按原全局范围停止七轴。详情 STOP AXIS 选择 1～4 时也停止整组四轮；5～7 单轴 STOP 保持原义。
- 每段实际停车确认后等待 1 s，再从该段实际姿态开始下一段。依次：+300x、-300x、+300y、-300y、(+200,+200)、(-200,-200)、+90°、-90°。结束 DONE，取消 CANCELLED，失败显示具体原因。任何一段失败不继续。

旧 `Doc/MOTOR_UI_DISPLAY_2026-10-23.md` 和其中截图描述的是实施前基线，保留追溯；当前概览标题和底盘视图以本文件/源码为准。

### 5.1 先核对机械和通信

1. 核对地址/物理轮位：1 FL、2 FR、3 RL、4 RR；确认 X 型滚子布局。实际非 X 型时先修正安装或明确变更模型，不用随意翻转公式掩盖问题。

### 5.2 光流尺度、轴向及偏置

1. 记录安装高度、地面材质/纹理、光学中心相对旋转中心的 offset_x/y（前正、左正）。只有实测光学中心确实在旋转中心，才可把零偏置视为已确认。
2. 保持车体无旋转，人工沿前/后/左/右各移动 500 mm，每个方向至少三次。每次记录映射后的累计 counts 起止值、质量、rejected/gaps/segments/clears；不用跨无效区间累计值计算尺度。
3. 先确认轴交换和符号，再求正的 X/Y mm/count 和安装角。一般关系为 `body_delta = R(mount_angle) * diag(scale_x,scale_y) * mapped_counts_delta`。轴近似对齐时尺度可用已知距离/主轴 counts 绝对值；有交叉轴残差时须拟合/修正安装角，不能仅分别改两个比例。
