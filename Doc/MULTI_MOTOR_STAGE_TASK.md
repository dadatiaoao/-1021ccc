## 1. 阶段目标与范围

在已接入 XM1605 扫码的野火 F429 工程上，将地址 1 的单电机通信扩展为同一 UART5 总线上的七电机通信：

1. 七台独立查询和显示实际速度、位置、状态、数据有效期与错误。
2. 七台可按地址使能、停止及下发受控的速度/位置指令。
3. 四轮支持一次提交四个不同速度，并通过厂家 0xAA 多电机命令成组发送。
4. 支持厂家“先缓存、再同步触发”机制的非阻塞事务，作为兼容/联调入口。
5. 三个机构轴支持方向、速度、加速度、脉冲数及明确的位置模式；本阶段不做 mm/角度机械标定。
6. 保留扫码、PB12 周期触发、会话锁定、RESCAN、触摸与显示，默认启动仍不自动运动。

本阶段交付通信基础与可手动触发的联调入口，不实现麦轮运动学、里程计、导航、机械臂动作编排、限位回零、舵机或完整比赛流程。七个电机无需七个串口。

## 5. 总线与协议工作项

### A. 一个总线管理器，七个节点状态

推荐建立 `MotorBus`，内部保存 `MotorNode/MotorSnapshot[7]`，整个 UART5 只有一个发送所有者。可以重构现有 service，也可新增 bus 后让旧接口适配，但默认应用只能运行一个总线调度器。

总线负责请求队列、优先级、发送与回包匹配、轮询、超时、迟到响应、分组事务和传输异常。节点负责地址/角色、测量值、字段时间戳、有效性、在线状态和错误计数。

解析结果必须带地址；单播事务按“地址 + 功能码 + 预期响应类型”匹配。未知地址、不相关功能码、过期/异步通知不能结束当前事务。保留拆包、粘包、噪声、载荷中含 6B 的处理，不把 IDLE 当帧尾。

在线状态与具体字段新鲜度分开：收到状态不等于位置也新鲜，故障节点不能让其它节点一起变成离线。UART 总线级故障则影响整条总线，清理/标记未决事务并使相关数据失效。

协议没有事务序号，本地 request_id 只能用于软件关联，不能彻底识别迟到的同地址同码回包。实现要说明隔离窗口、重试与丢弃策略；不能把迟到旧 ACK 误判成下一动作成功。

### B. 控制接口

| 接口意图 | 约束 |
|---|---|
| 按地址查询 | 1～7 的速度、实际位置、状态；启动/诊断可读硬件固件版本 |
| 按地址使能 | 显式请求；与实际使能状态确认分开 |
| 按地址速度 | 方向、速度、加速度、可选缓存标志 |
| 按地址位置 | 方向、速度、加速度、脉冲数、模式、可选缓存标志 |
| 四轮速度组 | 固定地址 1～4 的完整向量，单个 0xAA 包 |
| 同步事务 | 提交成员和命令，逐一准备并确认，最后触发；不允许随处单独调用广播触发 |
| 停止单轴/底盘组/全部 | 最高优先级；取消相关尚未发送动作并分别验证停止 |
| 状态与结果读取 | 区分排队、已发送、接收确认、执行、完成、拒绝、超时/未知、取消 |

位置模式应显式枚举：

- 00：相对上一输入目标位置。
- 01：相对坐标零点的绝对位置。
- 02：相对当前实际位置。

本阶段不假设机构已经回零或标定，应用层不得把绝对脉冲坐标宣传为机械绝对位置。位置验收若需要期望角度，必须提供并核对实际每圈脉冲数；电机反馈的 65536 计数/圈与指令脉冲数不是同一单位。

四轮 API 可接受有符号 RPM 向量，集中换算为方向+幅值；防止负数取绝对值溢出。CW/CCW 不等于车体前进/后退，本阶段不猜各轮安装方向。

### C. 多电机封装、应答与容量

- 0xAA 首版只聚合运动命令，不将多台读取混入同包。
- 手册规定运动聚合命令只有地址 1 回复。四轮包应匹配地址 1 的对应控制响应，不能等待四个 ACK；也不能凭一个 ACK 将四台全部标为成功。
- 本阶段常用聚合包采用同类子命令，尤其四条 F6；混合不同控制功能码的完整支持不是必需，避免自行猜多个确认的对应方式。
- 0xAA 内位置命令的“同步位”用于是否返回到位通知，不能与普通单播缓存语义混用。组包接口必须区分，默认不开启主动到位通知。
- `02` 是接收确认，`9F` 是异步完成通知；`12/22` 按对应命令语义处理，不能一概当格式错误或正常完成；保留 `E2/EE` 的原始含义。软件超时/传输异常单独分类。
- 单地址误差/状态/速度等实际反馈才用于确认执行；位置完成需结合本次目标、新鲜反馈、容差和超时，不能仅看之前遗留的“到位”标志。
- 零位移或已经位于目标的合法请求允许不发生位置变化，不能把旧演示的“必须观察到移动”条件机械套到所有位置动作。
- 扩大 `EmmCommand` 和 UART TX 缓冲；可用 128 字节作为七轴常见指令的有界容量。所有添加、总长度、DMA 长度和复制都检查边界，统一长度类型。七条 13 字节位置指令加外层共 96 字节，但是否开放这种包仍按应答与同步约束决定。
- TX 缓冲在硬件发送完成前不可重用；HAL_BUSY 不等于提交成功。检查现有固定 20 ms TX 看门狗与最大帧、波特率和调度抖动是否匹配，必要时按长度计算。

### D. 同步缓存事务

采用 `PREPARE → ACK_ALL → TRIGGER → VERIFY` 非阻塞流程；其中 ACK_ALL 仅适用于逐台缓存的单播阶段，不适用于 0xAA。

任一成员拒绝、离线、准备超时或取消时，不广播触发。一次仅允许一个同步准备事务；广播 0xFF 会触发总线上所有已缓存命令，不能假设其只作用于软件中命名的底盘组。

官方资料没有在本任务中证明“Stop/Disable 一定清除所有缓存”。部分准备失败后进入同步状态不确定/锁定状态；明确实施经资料与实测验证的清理/重新建立已知状态流程。未经确认不得解锁后直接发下一次广播。不要为清理缓存而随意触发未知动作。

对 0xAA 执行状态不确定也不自动切换另一种机制重发，避免相同位置动作执行两次。同步启动不代表同时到位。

## 6. 调度、故障和带宽

1. 优先级：停止及故障处理 > 控制/必要确认 > 常规轮询 > 诊断。
2. 四轮速度使用“最新完整向量覆盖尚未发送的旧向量”，不排队回放一串过期速度。位置动作是一次性事务，不能按同样规则悄悄覆盖或重复。
3. 同一总线上默认只等待一个可确定匹配的单播应答；广播/聚合采用各自明确的应答策略。
4. 查询允许有限重试，但一次失败后让出总线；掉线节点降低探测频率。不能对一个掉线节点连续长时间重试而拖住其它六台。
5. 运动 ACK 超时标记结果未知，不自动重复位置命令；先停止/查询/确认状态，再由联调流程决定下一步。
6. 停止可取消普通待发队列及查询等待，发送前处理已在途帧与最小间隔，禁止随意拼接截断帧；迟到响应不能复活被取消动作。停车后没有新反馈时显示未确认。
7. 地址 1 失联时，0xAA 包可能没有 ACK，但其它成员仍可能执行；四轮组立即进入故障处理，不可把此情况当作“整组没动”而重发。
8. 底盘任一轮故障时停止整个底盘组；三个机构轴按受影响范围处理。地址 6 升降轴不默认失能，停止与松轴分开；通信控制不能保证断电后的负载保持。
9. 故障恢复只恢复查询，不自动使能、不重放旧动作。四轮速度命令带有效期，上层停止更新则请求停车；MCU 停机或物理通信失效时该软件机制不构成硬件停车保证。
10. 接收 Pump 和绘图有单次处理预算，保持扫码触发/接收及时运行，不在主循环中无限清空高速输入。

厂家同步例程使用 10 ms 间隔，当前单机服务使用至少 5 ms。新实现先将间隔集中配置，以 10 ms 作为保守联调起点，实测后调整；所有间隔通过时间状态机实现，不使用 HAL_Delay。

不要要求七台各自每 100 ms 查齐三个量。可采用以下起点，后续根据总线统计实测调整：

| 运行状态 | 调度建议起点 |
|---|---|
| 默认只读 | 每台三个反馈约 500 ms 一轮，按事务交错，总计约 42 次查询/秒 |
| 四轮运动联调 | 四轮整组速度最多先按 10 Hz 更新；各轮速度约 5 Hz |
| 全节点基础状态 | 每台约 2 Hz |
| 机构位置 | 每轴约 2 Hz；当前运动/接近目标的轴临时提高反馈优先级 |
| 掉线节点 | 降频探测，不占用正常轮询频率 |
| UI | 延续约 100 ms 局部更新 |

以上是设计初值而非性能保证。字段有效期按各自轮询周期设置，不能继续以“三项都在 500 ms 内”判所有节点在线。报告实际更新间隔、最长数据年龄、超时和总线占用；停止响应不得受低频基础轮询限制，停车后优先查询相关轴。
