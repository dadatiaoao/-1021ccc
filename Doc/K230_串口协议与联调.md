# K230 与 STM32F429 串口协议和联调（2026-10-24）

本次已把 STM32 接收端、发送端和触摸屏联调入口接入现有 Keil 工程。对端使用现有 `k230烧录进去的程序/transport_vision`，不需要另换模型或修改通信格式。当前交付实现视觉通信与显示；比赛 READY/START、机构回零、自动抓放和评分闭环仍是后续任务。

本仓库为 STM32 工程，K230 完整运行目录与模型另行部署。`Tests/k230_reference/vision_protocol.py` 保留了 K230 纯协议模块的原样副本，使独立克隆仓库后也能运行报文兼容测试，不依赖本机仓库外的文件夹。

## 1. 接线与烧录

| K230 丝印 / 功能 | STM32F429 端口 | 方向 |
| --- | --- | --- |
| 11 / TX2（GPIO IO11） | PA10 / USART1_RX | K230 → STM32 |
| 12 / RX2（GPIO IO12） | PA9 / USART1_TX | STM32 → K230 |
| GND | GND | 两板共地 |

参数：**115200，8 数据位，1 停止位，无校验，无流控，3.3 V TTL**。IO11/IO12 是 K230 GPIO 编号，PA9/PA10 是 MCU 端口名称；不是连接器第几个针脚。按板上丝印找对应端口，发送接接收。两板可分别正常供电，信号线不要接 RS232 或电机电源。

USART1 现在由视觉专用，原来的 `printf`、`Usart_SendString` 输出已禁用，避免文字混入二进制报文。不要再把串口调试器 TX 并接到 STM32 PA10 上形成两个发送源。USART3 扫码和 UART5 电机仍使用各自通道。

Keil 打开 `Project/YH-F429.uvprojx`，目标 `LCD`，使用 ARM Compiler 5.06 update 7；生成 `Output/YH-F429.hex`。先把该 HEX 烧入 STM32。STM32 固件不能复制进 K230 的 sdcard 代替烧录。K230 保留已部署的 `/sdcard/main.py`、`transport_vision` 和两个模型，运行其主程序。

## 2. 屏幕联调

1. 上电先进入原 QR 页，点击左上角 **QR / VISION [tap title]** 进入视觉页。进入页面和上电本身不发送 SCAN。
2. 等 K230 完成模型初始化，**HB:ON** 表示收到最近 3 秒内的有效心跳。K230 启动预览时可以显示两个模型，但不会主动报告目标坐标。
3. 点击 **NEXT M** 那一行循环选择模式。点击下一行左、中、右三段分别切换颜色、区域和工位。参数选好后点左下 **SCAN** 生效；`NEXT` 是待提交参数，状态行 `M` 是当前请求模式。
4. STM32 自动发送 STOP → SET_CONTEXT → SET_COLOR → SET_TARGET → SCAN，逐条等待 ACK。状态由 CONFIG 变为 ACTIVE 后查看坐标；配置进行中再次点 SCAN 不会叠加请求。
5. 坐标显示为 `ID / X / Y / FLAGS`。`--` 表示没有新鲜、匹配当前请求的结果。二维码模式显示 `QR:156+123+516+231` 这样的完整任务码。
6. 中间 **STOP** 仅停止视觉扫描，并立即清除旧目标；**BACK** 返回原 QR 页，不停止已经启动的扫描。原其它页面的全局 STOP 同时提交视觉 STOP 和原电机停止请求。

| 模式 | 屏幕名称 | 用途与边界 |
| --- | --- | --- |
| 0 | QR | 扫任务二维码，连续一致后由 K230 发送一次 |
| 1 | COLOR | 指定颜色物料中心候选 |
| 2 | STATION | 识别整个大圆环及工位数字；旧 RING 帧是大框中心，扩展帧可能使用局部几何候选 |
| 3 | PICK | 转盘抓取前视觉候选，抓取标定未完成时不会宣称 PICK_READY |
| 4 | GEOMETRY | 大圆环内局部几何候选；几何失败报告未找到，不退回大框中心 |

颜色编号：1 红、2 黄、3 深蓝、4 绿、5 黑、6 浅蓝。区域：1 粗加工、2 暂存。工位 POS：1～3，对应印刷数字；**不是最内圈“1 环”，也不是评分环数**。

联调页的 SCAN/STOP 不调用电机或夹爪 API。联调页递增的 POSE 只是软件测试上下文，不能证明相机实际到了某个姿态。正式任务应由 STM32 在相机运动完成后传入相应姿态编号。

## 3. 线上的每一帧

```text
AA LEN CMD PARAMS CHECKSUM
LEN = 1 + 参数字节数，范围 1～13
帧总长 = LEN + 3，最大 16 字节
CHECKSUM = (CMD + 所有 PARAMS 逐字节相加) & 0xFF
u16 使用大端；i16 为大端二进制补码
```

这是累加校验，不是 XOR 或 CRC，不含帧头和 LEN。每帧参数长度必须与命令匹配；校验正确的错误长度包也会被服务拒收。解析器支持拆包、连续多包、噪声恢复及参数内出现 AA，半帧空闲 100 ms 后清除。

STM32 → K230：

| CMD | 名称 | 参数 |
| --- | --- | --- |
| 21 | SCAN | mode:u8，0～4 |
| 22 | STOP | 无；停止直到下一次 SCAN |
| 23 | SET_COLOR | color:u8，1～6 |
| 24 | RESCAN | 无；保留模式，不能解除 STOP |
| 25 | SET_TARGET | zone:u8，1～2；position:u8，1～3 |
| 26 | SET_CONTEXT | request_id:u16；camera_pose_id:u16，启用扩展结果 |

K230 → STM32：

| CMD | 名称 | 参数字节数 / 含义 |
| --- | --- | --- |
| 10 | TASKCODE | 12 个数值字节，不是 ASCII，STM32 补回三个 `+` 并严格验证任务码 |
| 11 | FOUND | 9：color:u8、cx:u16、cy:u16、offset:i16、distance:u16 |
| 12 | NOTFOUND | 0：立即撤销旧目标 |
| 13 | PLACE_CHECK | 3：zone、position、ok；只保存为图像候选 |
| 15 | HEARTBEAT | 0：约每秒一次 |
| 16 | RING | 5：position:u8、cx:u16、cy:u16 |
| 17 | OBSERVATION | 12：request:u16、pose:u16、frame:u16、flags:u8、target:u8、cx:u16、cy:u16 |
| 81 | ACK | 2：被确认的 CMD、status；0 接受 / 1 参数错误 |

坐标范围为 **1280×720 协议像素**，不是当前 640×360 AI 输入像素，也不是毫米。offset 单位为 0.1 度；distance 单位 cm，默认 0 表示未知距离。TASKCODE 完整结构仍是 `C1+P1+C2+P2`；原 USART3 扫码服务独立保留，视觉任务码不会悄悄覆盖它。

FLAGS：01 FOUND、02 STABLE、04 PICK_READY、08 FULL_BOX、10 AMBIGUOUS、20 CALIBRATED、40 REFINED、80 STALE，均为十六进制位掩码。无 FOUND 时 x=y=0 表示没有目标；有 FOUND 时图像原点 (0,0) 可以是有效坐标。frame 是 K230 软件采图调用序号，16 位回绕，不是两板同步时间。

手工串口助手发送示例（HEX）：

```text
停止                 AA 01 22 22
设置红色             AA 02 23 01 24
粗加工区、工位 2     AA 03 25 01 02 28
上下文 request1 pose2 AA 05 26 00 01 00 02 29
开始色块模式 1       AA 02 21 01 22
开始大圆环模式 2     AA 02 21 02 23
开始几何候选模式 4   AA 02 21 04 25
K230 心跳            AA 01 15 15
```

用电脑单独模拟时先断开另一发送端，勿与 STM32 程序同时抢写 K230 串口。

`QrApp_Init` 已完成一次 `BspVisionUart_Init` 和 `VisionService_Init`，主循环已接入 Pump/Process，不要在另外的循环里重复初始化 USART1 或另定义 HAL UART 回调。

后续任务模块可在无在途配置时调用（返回 1 表示请求已排队，不表示 K230 已开始工作）：

```c
/* app 为长期保存的 QrApp；每次姿态完成后给出相应 pose_id。 */
uint32_t now = HAL_GetTick();
int queued = VisionService_Start(&app.vision, 2u, 1u, 1u, 2u, pose_id, now);
/* mode2，红色，粗加工区，数字2工位；等待 ACTIVE 和新的匹配结果。 */
if (VisionService_TargetFresh(&app.vision, now)) {
    uint16_t x = app.vision.observation.cx;
    uint16_t y = app.vision.observation.cy;
    /* x/y 仅为当前视觉候选，先做标定和物理条件校验，再设计动作。 */
}
/* 需要停止时调用；状态 STOPPED 只表示 K230 接受 STOP。 */
VisionService_Stop(&app.vision, HAL_GetTick());
```

后续控制应优先使用 `observation` 与 `VisionService_TargetFresh`，不要把 `legacy_valid` 或 `place_candidate` 直接当作动作许可。上述 x/y 示例变量用于说明读法，实际模块按需使用，避免未使用变量警告。

## 5. 超时和结果边界

- 一次只等一条命令 ACK；3 秒超时进入 FAULT，不盲目重发扫描命令。TX 持续忙也有 3 秒上限。STOP 可取消尚未完成的配置。
- 扩展结果必须匹配请求号、姿态号、当前目标，以及递增的软件帧号；旧帧和重复帧忽略，支持 65535→0 回绕。模式4还要求 REFINED。
- 目标 500 ms 后失效；心跳超过 3 秒离线，ACTIVE 转 FAULT。串口错误、队列溢出、NOTFOUND、STOP、新请求都会撤销旧目标。心跳恢复不会自动恢复旧动作或旧请求，排除故障后再次点 SCAN。
- DMA IRQ 搬运字节和接收时间，前台每次至多取 128 字节；UART/RX DMA/TX DMA 使用相同抢占级 3，串行进入生产者。TX 独立缓冲直到完成，错误恢复不抢改在途数据。DMA 缓冲位于片内 SRAM。
- ACK 本身没有请求号，不能从协议层彻底分辨同一个 CMD 极迟到的重复 ACK。因此本服务串行提交、不自动重试；扩展目标再用 request/pose 过滤。二维码 TASKCODE 也是旧的无上下文消息，若要用于整场动作还需升级双端协议；当前只作为独立视觉结果保存和显示。
- `TargetFresh` 表示新鲜的目标候选，不等于稳定、抓取成功、内环精度、落料成功或评分达标。是否要求 STABLE/FULL_BOX/CALIBRATED 等，应由经过实物验证的任务逻辑决定。

本次测试能证明软件组包、解析、过滤、界面入口和 HAL 模拟恢复逻辑；不能代替真实接线、串口波形、K230 推理速度及抓放/圆环精度验收。
