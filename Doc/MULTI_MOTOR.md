### 可照着操作的步骤

1. **逐台确认再接总线。** 在电机本身/厂家工具中核对 Emm 固件、唯一地址 1～7、115200/8N1、固定 `6B`、Response=`Receive`，关闭未安排的定时回传/到位通知。程序不改地址、不写持久参数、不恢复出厂、不升级固件。版本可通过 `MotorBus_ReadVersions(&app.motor)` 诊断读取，在调试器查看 `nodes[i].firmware/hardware/version_valid`。
2. **接线与上电。** UART5 PC12 TX → 电机 R/A/H；PD2 RX ← 电机 T/B/L，GND 共地。按 X42S 手册第 26 页 TTL 多机图和实际硬件版本接入七台，电机按其额定要求独立供电。USART3 PB10/PB11、PB12/TRIG 保持现有扫码接线。先逐台验证反馈，再接七台。下载当前固件，上电默认 QR 页，不自动运动。
3. **查看七机。** 点底部 MOTOR。`WAIT` 表示尚无匹配反馈，`OFF` 表示链路失效，`STALE` 表示部分反馈过期。RPM 或状态 `--` 不是零速/无故障的实测结论。点某行进入详情，`P/T` 单位为编码器计数（65536/圈），不是指令脉冲、毫米或机械角度。
4. **扫码并行。** 在 MOTOR 页持续扫码，点 QR 回看锁定任务；RESCAN 仍只开启新扫码会话。PB12 仍为 1000 ms 周期、800 ms 低电平；模组必须使用已核对的手动/电平触发模式。锁定后继续触发只累加 DUP/IGN。
5. **确认联调参数后重新构建。** 编辑 `User/motor/motor_test_config.h`。默认 `MOTOR_TEST_CONFIGURED=0`，位置/四轮/同步入口显示 `CONFIGURE motor_test_config.h`，但单轴 SPEED 点动在 `MOTOR_BENCH_JOG_ENABLED=1`（默认）时可用（10 RPM、1 s）。在脱开负载或已确认不会越程的条件下，确认方向、低速和行程后把 `MOTOR_TEST_CONFIGURED` 置 1；机构位置还必须把 `MOTOR_TEST_PULSES_PER_REV` 从 0 改为实际已核对值。不要把本次模拟使用的 3200 当成实物事实。修改后运行本文第 5 节的测试/构建命令，再下载。即使启用参数，上电仍只读。
6. **进入手动并使能。** MOTOR 页点底部左侧 MANUAL，标题变成 `MOTOR MANUAL`，左按钮变为 READ ONLY。点目标行，详情初始动作是 ENABLE；点 `RUN ONCE`，等待新状态反馈确认使能。使能 ACK 不等于已锁轴；详情状态字 bit0 才是读回使能。四轮联调前分别对 1～4 执行。程序不自动替你使能其它轴。该 MANUAL 门控是 UI 层语义；通过 API/任务状态机直接调用时不再需要它，但仍要满足新鲜、使能、无故障条件。
7. **单轴速度。** 在详情 `ACTION: ... [tap to cycle]` 这一行点击，选 SPEED，再点 RUN ONCE。模板为方向 0、10 RPM、加速度 100、1000 ms 有效期。只有该地址运行；有效期结束请求停止。CW/CCW 是电机方向，不代表车体前进/后退。单轴速度也受同一总线和故障处理管理。
8. **四轮速度。** ACTION 选 WHEELS 0xAA，再点 RUN ONCE。默认完整向量为 `{10,-12,14,-16}` RPM，可在 `MOTOR_TEST_WHEEL_RPM` 集中修改；正负只映射 CW/CCW，不猜安装方向。每次点一次提交一个完整向量，1000 ms 后停车。连续控制通过 API 最多先以 10 Hz 刷新，软件只保留尚未发送的最新完整向量。观察四个节点实际 RPM，`GROUP ACK1 / VERIFY EACH` 仅是地址 1 的接收确认。
9. **机构位置。** 先回 BACK，再选 5 ARM、6 LIFT 或 7 TRIM；ACTION 选 POSITION，点 RUN ONCE。模板是 10 RPM、32 脉冲、模式 02、8000 ms 完成超时。模式可配置为 00/01/02；00 必须已有本程序已知的上一输入目标，否则拒绝。长按不重复执行。`ACK ONLY`、`EXECUTING` 和 `COMPLETE` 分开显示；只有目标容差内且新速度为 0、新状态到位，才 COMPLETE。未做机械零点/限位，不宣称准确 50 mm 或机械绝对坐标。
10. **同步联调。** 默认 `MOTOR_SYNC_CLEAN_BOOT_CONFIRMED=0`，入口拒绝并显示 SYNC LOCKED。这是因为没有实物证据证明 Stop/Disable 会清除缓存。受控实测前必须对**全部电机重新上电**、确认无其它写总线端和残留缓存，再将此宏置 1 构建用于该次受控启动；MCU 单独复位不能证明缓存干净。使能四轮，ACTION 选 SYNC WHEELS 后 RUN ONCE。任何准备失败/取消/总线异常后保持锁定，没有 UI/API 运行时解锁入口；STOP 不解锁。不得只复位 MCU、保留电机供电后再次使用配置为 1 的固件来绕过锁定。当前清理规则仍待实测，日常交付配置始终为 0。
11. **停止。** 底部 STOP 在 QR、七机概览、详情页均可点，停止 1～7。详情页右侧 STOP AXIS 只停选中轴，左下 STOP WHEELS 停 1～4。退出 MANUAL 点 READ ONLY 也请求全停。程序不因普通停止失能升降轴；没有新反馈时显示 `STOP UNCONF`，超时为 `UNKNOWN`。`STOPPED` 必须有停止发送之后的新零速和无故障状态，不能只凭停止 ACK。停止结果不代表物理抱闸或断电负载保持能力。
12. **掉线恢复。** 联调中断开某台通信，确认其它节点/扫码仍更新并查看停止状态。恢复连接后等待探测和反馈（掉线探测间隔约 2 s），不会自动使能或继续运动。若节点处于 `UNKNOWN`，在收到其新的零速/无故障反馈并经过稳定窗后会自动恢复为 `STOPPED`/`IDLE`（`MOTOR_UNKNOWN_AUTO_RECOVER_MS=0` 可关闭），随后可显式 ENABLE/提交新动作；仍在转或有故障时 `UNKNOWN` 继续阻止新运动。同步缓存故障不会因通信恢复而解除。

触摸命中沿用原坐标：底部 y=232～263，左 x=8～151 切手动/只读或 RESCAN，中 x=160～239 全 STOP，右 x=248～471 QR/MOTOR。详情 ACTION 行 y=136～153；RUN/STOP AXIS 行 y=180～197（左/右半）；STOP WHEELS/BACK 行 y=202～219。一次手势只处理按下边沿，所有手指释放后才开始下一次手势。屏幕真实触点与这些坐标是否一致待实测。

| 聚合边界 | 仅同类运动子命令，拒绝读取/混合/重复地址/越界；FD 聚合的最后标志必须为 0（不开到位通知），不能当作缓存标志。总线当前只公开四轮速度聚合，未开放任意位置聚合调度 |
| 传统同步 | 每条单播 cached=1，逐一 ACK；10 ms 最小间隔；全部准备后发 `00 FF 66 6B`，匹配地址 1 的 FF 应答；之后仍逐轴验证，不能由 FF ACK 宣称同时到位 |
| 返回语义 | 02 接收确认；9F 异步通知单独记录、不结束当前命令；12/22 为当前位置/限位条件下未运动的返回，在本阶段非回零动作中保留原码并拒绝；E2 条件/参数不满足，EE 格式错误 |
| 版本 | 1F 返回 7 字节，固件和硬件各为 16 位，按 X42S 新手册处理，不沿用旧版本 5 字节假设 |
| 容量 | EmmCommand 与 TX 持久缓冲 128 字节，长度类型 uint8_t（上界 128，传 HAL 时扩为 uint16_t）；每次追加/复制/发送检查边界。七条 FD 的 96 字节封装经主机检查 |

`Emm_Velocity/Move/Stop` 等旧接口及单机 service/demo 保留，供旧回归使用；默认应用只创建一个 MotorBus，旧 service 不并行运行。新运动接口使用 `Ex` 构帧与总线参数检查；不能绕过总线直接调用 BSP send。

## 3. 调度、状态与安全边界

`QrApp_Process` 调用 `BspMotorUart_PumpBus → MotorBus_Process`，再沿用触摸、PB12、USART3/扫码会话和 UI。HAL 回调仍唯一，由原 `bsp_uart_callbacks.c` 按实例分发；时钟、引脚、HAL 1.7.3、AC5、LCD、触摸、扫码协议均未迁移或升级。

- 一个活动请求，7 槽有界普通队列（每节点不重复排队）、一个最新四轮向量槽、一个同步事务。优先级为停止 → 同步准备/触发 → 普通控制/四轮组 → 停止反馈确认 → 轮询 → 版本诊断。停止可取消相关普通队列、四轮槽以及查询等待，保留已在途 DMA 帧到完整发送结束。
- 只在地址、功能码和预期响应类型匹配已发送请求时发布数据。9F、未知地址、错误长度、噪声、其它请求的响应不能确认当前动作；按长度解析，载荷中的 6B 不作帧尾，IDLE 仅搬字节。无法归属节点的坏字节计入 `bus.parser.rejected`，不伪造节点错误。
- 正常字段周期起点 500 ms；运动中的速度和机构位置起点 200 ms；状态仍为 500 ms。60 ms 应答超时；查询失败让出总线，下一次读安排在至少 500 ms 后，连续两次失败降为约 2 s 探测，不原地连续重试。成功后回到正常轮询。字段新鲜度 1600 ms，与 `last_rx_ms` 判定的在线状态分开。
- 超时/取消后该节点隔离 120 ms，再开始新的普通读/控制；停止使用不同功能码可抢占等待。位置/速度命令超时均不自动重发；四轮不在 ACK 不确定时改用同步补发。协议没有序号，软件 request_id 仅用于本地关联。**超过隔离期才来的同地址同码回包仍无法从线上可靠区分**；运动超时先停并验证，UNKNOWN 阻止新动作，不能承诺任意迟到 ACK 都能识别。需实测固件最大响应延时后核定窗口。
- 运动仍要求新鲜、在线、健康、已使能的反馈；`MANUAL` 仅是 UI 层的显式意图，驱动层可用 `MOTOR_DRIVER_REQUIRE_MANUAL=1` 恢复旧强制；让状态机直接调用时由上层保证显式意图。使能 ACK 与状态读回分开。位置需已核对每圈脉冲数；00 还需已知上一目标。中止/故障/速度模式会使上一位置目标关系失效；未建立目标时拒绝 00，使用经确认的 02 或 01。无未确认停止意图的 `UNKNOWN` 在收到新的零速/无故障反馈并过稳定窗后自动恢复（`MOTOR_UNKNOWN_AUTO_RECOVER_MS`，默认 500 ms）；仍在转/有故障时保持拦截。未配置参数时默认只允许单轴低速点动（`MOTOR_BENCH_JOG_ENABLED`），位置/四轮/同步仍需 `MOTOR_TEST_CONFIGURED=1`。
- 速度请求带 100～5000 ms 有效期，从提交时计时；最新排队向量不延长已运行向量的期限。四轮发送最多先按 100 ms 间隔。位置是一次性事务，1000 ms 内未发送就取消；执行超时范围为 100～60000 ms。零位移允许无位置变化；位置完成必须有本次发送之后的新位置/零速/到位反馈且目标误差在 128 编码器计数内（可配置）。
- 自本程序发起的运动期间，节点失联、查询超时、状态保护/堵转/失能或执行超时会请求停止；任一轮影响四轮组，机构按相关轴处理。恢复只查询。默认只读不接管外部控制器已在运行的电机，MCU 复位也不等于电机已停。
- Stop 不自动 Disable，尤其不松开地址 6。STOP ACK 不确认停止；发送后的新速度=0、状态无保护/堵转才 STOPPED，缺反馈保持未确认/超时 UNKNOWN。未确认意图不会因超时或 UNKNOWN 自愈被清除；首次提交及两次快速尝试按至少 200 ms 间隔，此后至少 1 s 一次，轮转轴并给反馈查询让出事务。重复 STOP 合并，不重置首次期限或证据基线；协议隔离/事务繁忙会延后发送。零速与状态必须在首次 STOP 提交之后新取得，ACK、DMA 完成和旧零速均不够。缺反馈持续重试，只有新鲜零速/无保护或堵转证据后确认，始终不重放运动。界面概览 `STOP?`、详情 `STOP UNCONF` 保留未确认状态。
- 同步在准备/触发/验证中被中止、拒绝、超时或传输错误，锁定后续同步；不能假设 Stop/Disable 清空缓存。默认启动也锁定同步。当前没有已实测的运行时清缓存/解锁流程。
- BSP 发送先复制到静态 TX 缓冲，HAL_BUSY 返回未提交，不复用在途缓冲；看门狗为 `20 + ceil(length*10000/115200)` ms，128 字节为 32 ms。电机 Pump 每次最多 128 字节，扫码 Pump 保留原有预算；UI 每次至多绘制一个 480×4 条带或两个字符，100 ms 限制快照请求，作业每轮推进。UART5 先隔离接收错误再清 IDLE，DMA 回调同样门控；恢复丢弃 DMA/SW 队列及协议半帧。接收不可用时阻止全部 TX（包含 STOP），停止意图继续保留至链路恢复；没有另开不能验证反馈的 TX-only 通道。RX 恢复失败至少间隔 100 ms，验证本次 DMA READY→BUSY、EN/DMAR/RxState/错误码；TX 启动也检查本轮 DMA 状态，RX 错误不主动中断在途 TX，看门狗才处理 TX 故障。真实主循环抖动需实测。

调试器可查看 `app.motor`：`nodes[i].data`、`action/request_id/target_counts`、`poll_samples/max_poll_gap_ms/max_age_ms/rejected_commands`，以及总线 `tx_frames/tx_bytes/rx_bytes/timeout_count/ignored_frames/transport_errors/max_step_ms`。这些是统计，不是硬件停车保证。MCU 停机、总线物理断开或断电负载保持仍需硬件方案。

## 4. API 最小示例

所有调用在同一前台上下文，不在中断直接提交；使用当前 `HAL_GetTick()`。以下是调用示意，不在启动或扫码事件中自动执行。

```c
MotorAction a = {0};
MotorBus_SetManual(&app.motor, 1u, now);
MotorBus_Enable(&app.motor, 5u, 1u, now); /* 再等待状态读回 bit0=1 */
a.command = Emm_MoveEx(5u, 0u, 10u, 100u, 32u, EMM_REL_ACTUAL, 0u);
a.pulses_per_rev = confirmed_pulses_per_rev;
a.timeout_ms = 8000u;
MotorBus_Submit(&app.motor, &a, now);    /* 检查返回值及节点 action */
MotorBus_Stop(&app.motor, MOTOR_ALL, now);
```

`MotorBus_Wheels` 接受完整 `int32_t rpm[4]`，先检查 -3000～3000 再取绝对值，拒绝 INT32_MIN；`MotorBus_Sync` 接受 1～7 个带缓存位的 MotorAction，仅允许一个准备事务，调用方不能直接广播触发。需要对同步位置动作设置各自已核对的 pulses_per_rev/timeout；初次同步仍受缓存锁定限制。
